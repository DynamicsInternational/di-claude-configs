# /al-mutate — AL Mutation Testing (LethAL)

**LethAL** ([SShadowS/LethAL](https://github.com/SShadowS/LethAL), MIT, alpha) replaces `al-mutate`
(`MSDyn365BC.AL.Mutate`), which is deprecated and no longer maintained. Its own agent reference is
`docs/using-lethal-from-an-agent.md` in the LethAL repo — read it for anything not covered here.

## How It Works

1. Copies the app to a temp directory — **your source tree is never modified**.
2. Runs the test app once as a baseline (a red baseline makes the affected mutants unscoreable).
3. Applies mutations (generic operators plus AL-specific ones: `remove-testfield`, `remove-setrange`,
   `remove-calcfields`, `swap-rec-xrec`, `validate-to-assign`, `swap-modify-flag`, …), runs the tests
   covering each mutant, records a verdict.
4. Writes a JSON report; `lethal explain` turns it into a readable summary.

## Backends

| Backend | Runs on | Role |
|---------|---------|------|
| `bcdev` | BC sandbox / dev container (single-tenant, **never production**) | **Authoritative** — the numbers you report |
| `al-runner-v3` | In memory (al-runner v3) | Fast and not authoritative — **refused on Windows**, so on our Windows machines only from Linux/WSL or a Linux container |

`al-runner-v3` differs from BC (duplicate-key `Insert` does not fail, tests reported *not run* neither
kill nor survive, selecting one test runs its whole codeunit). Use it to explore, never to quote a score.

## Prerequisites

- **LethAL binary** — no release yet: build from source (Bun 1.x), the binary then runs standalone.
  ```bash
  git clone https://github.com/SShadowS/LethAL && cd LethAL
  bun install && bun run build:binary      # → build/lethal-<version>-windows-x64.exe
  ```
- **AL Language extension** (`alc`, `altool`) — or `bcdev.alcPath` / `bcdev.altoolPath` in the config.
- **bcdev backend**: `bc-dev-mcp` (spawned through `bcdev.mcpCommand`) and the **`LethAL Control`** app
  (built from the LethAL repo) published to the server.
- **`lethal.config.json`** — generated by `lethal init`; fill server and credentials. Credentials go in
  `bcdev.env` (`BC_DEV_USER`, `BC_DEV_PASSWORD`), never committed: keep the file out of git.
- **Three object IDs** for LethAL's injected objects (default 79197–79199; `init` picks them from the
  app.json ranges) — check they do not collide with the app or the test app.
- A **green** test app.

## CLI Reference

```bash
lethal init   --project ./app                         # starter lethal.config.json
lethal doctor --config ./app/lethal.config.json       # read-only pre-flight check

# Plan without touching a server
lethal run --project ./app --backend bcdev --dry-run --only "src/ItemImport/**"

# Scoped run (unscoped runs on real projects are refused; >1,000 sites needs --allow-large-run)
lethal run --project ./app --tests ./test --backend bcdev \
           --only "src/ItemImport/**" \
           --db  .dev/<task-slug>/lethal.sqlite \
           --out .dev/<task-slug>/06-mutations.json

lethal explain .dev/<task-slug>/06-mutations.json     # what the results mean
lethal verify  ...                                    # does a new test kill a named survivor?
lethal run ... --resume                               # continue an aborted run
lethal run ... --skip-known-survivors                 # skip survivors of a previous finished run
```

Other useful flags: `--operator <name>` (repeatable), `--tests-only <glob>` and
`--exclude-test <Codeunit.Method>` (both **can change verdicts** — the report is marked `tests-narrowed`),
`--mutant-timeout-ms`. Exit codes: 0 completed · 1 error · 3 quarantined (verdicts not trusted) · 4 nothing scored.

Scope with `--only` on the files of the business area under review — never the whole app.

## Verdicts

| Verdict | Meaning |
|---------|---------|
| `killed` | A test failed — good |
| `survived` | All tests passed — test gap lead |
| `no-coverage` | No test ran this code |
| `timeout-killed` | Ran past its budget — weakest kill evidence |
| `known-survivor` | Carried from an earlier run, not re-measured |
| `error` | No verdict — never counted |

Score = share of mutants killed. Coverage attribution per survivor: `exact` (a test executed that
procedure) or `object` (only the same object — reaching the line is unknown).

## Handling Results

- **Survivors are leads, not proven gaps** — some are equivalent mutants. For each, name the business rule
  it weakens and the test that should catch it.
- **`no-coverage`** on business logic → a missing test, not a weak one.
- **Exit 3 (quarantined)** → the server state is not trusted; investigate before reading any verdict.

## Limits

- Tests run without GUI: `Confirm` returns its default, `Page.RunModal` errors, tests that may open a
  `TestPage` are refused (*not run*). Rules covered only by such tests are not mutation-verified here.
- Extension objects get object-level coverage only.
- **The mutated build stays published** (at a version above the app's): afterwards, raise the app version,
  rebuild and republish the app, then republish the test app.
- Alpha: check `lethal --version` and the README when a flag or output differs from this page.

## Integration with /verify-tests

`/verify-tests` uses LethAL for its mutation sweep. Invoke `/al-mutate` directly for a standalone run
without the full adversarial audit.
